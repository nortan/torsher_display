# 9. История изменений и решения

Новые записи добавляются сверху.

## Бегунок времени показа слайда

В настройках слайда вместо двух полей времени — один бегунок «С–По» (шаг 15 минут).
По умолчанию — все сутки; диапазон пишется в `schedule.from`/`schedule.to` (`HH:MM`),
пустые значения означают все сутки, «По» левее «С» — показ через полночь.
Значок расписания в списке слайдов обновляется сразу при движении бегунка.

## Вкл/выкл экранов у каждого дисплея свой

Исправлено: выключение экрана в разделе «Экраны» при выбранном дисплее больше не выключает его
на остальных дисплеях. У дисплея появился `display.slideEnabled: {id слайда: true/false}`;
общий `slides[].enabled` остаётся значением по умолчанию. Список, галочки и предпросмотр
обновляются при переключении дисплея; «Все экраны» по-прежнему задаёт общее значение.

## Горизонтальный предпросмотр крупнее

Предпросмотр горизонтального дисплея в админке стал вдвое шире (до 760 px; на узком окне —
половина ширины), чтобы кадр было видно без прищуривания. Вертикальный предпросмотр остался
прежним, при переключении дисплея ширина и пропорции меняются автоматически.

## Оформление и шапка для каждого дисплея

В «Анимации и оформлении» появился выбор дисплея. Все настройки раздела — переходы, анимация,
шрифты, палитра и цвета, акцент, фон, шапка с названием/логотипом, бегущая строка и работа
экрана — сохраняются в `data.displays[*].settings`, `cafe`, `ticker` и применяются только к
выбранному дисплею. «Общие настройки» остаются значениями по умолчанию; новый дисплей копирует
их при создании. Плеер и предпросмотр сливают собственные значения с общими, поэтому старые
данные работают без миграции.

## Экраны выбранного дисплея и формат предпросмотра

В «Экранах» появился выбор дисплея: список, порядок и добавление слайдов относятся к выбранному
дисплею; «Все экраны · без дисплея» оставляет общий список. ✕ у дисплея убирает слайд только из
его набора, в общем списке — удаляет совсем. Предпросмотр и его рамка следуют ориентации и
разрешению выбранного дисплея — в том числе сразу при смене ориентации/разрешения в «Дисплеях».
Новый дисплей получает все текущие экраны; пустая программа по-прежнему означает «все слайды».

## Подписи разрешения в админке

Исправлено: в карточке дисплея выпадающий список «Разрешение» показывал `[object Object]` вместо
«2K (1920)» и «4K (3840)». Само значение сохранялось верно — сломано было только отображение
подписей: общий `select()` в `admin.js` не умел брать текст из объекта с полем `label`.

## Разрешение дисплея 2K / 4K

У каждого дисплея есть `resolution`: `1920` (2K, по умолчанию) или `3840` (4K). Для вертикали
физический холст — 1080×1920 или 2160×3840, для горизонтали — 1920×1080 или 3840×2160.
Логические раскладки общие, элементы масштабируются пропорционально. Старые дисплеи без поля
нормализуются как `1920`; это значение также добавлено в `content/data.json` для основного дисплея.

## Обновление контента на сервере

`POST api/update.php` (вход + CSRF) записывает `content/data.json` через тот же `save_data`,
что и обычная публикация. Кнопка «Обновить контент из репозитория» делает это из админки без
черновика. Workflow `deploy-ftp.yml` вызывает обновление после выкладки, поэтому сервер получает
версию данных из репозитория.

## Дисплеи и ориентация

В `data.displays` у каждого экрана есть имя, ориентация, разрешение и упорядоченная программа
id слайдов. Параметр `?display=` выбирает программу; без него работают все слайды вертикально.
Админка позволяет создавать дисплеи, менять программу и просматривать её в предпросмотре.
Дисплеи, слайды, блюда, события и настройки поддерживаются и в MySQL, и в файловом хранилище.

## Принятые решения

- **Без CDN:** библиотеки лежат в репозитории, чтобы экран работал без интернета.
- **Одна модель:** `shared/model.js` используется экраном, админкой и сборкой.
- **Публикация целиком:** данные заменяются одной операцией, а не набором построчных правок.
- **Анимация на каждый показ:** `gsap.context` + `revert` не дают ТВ-браузеру копить состояние.
- **Локальный Swiper CSS:** `vendor/swiper/swiper-flat.css` не использует nesting, который не понимают
  встроенные браузеры телевизоров.
- **Шрифты:** Calibri не распространяется из-за лицензии Microsoft; используется системный шрифт,
  иначе Carlito.
