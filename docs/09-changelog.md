# 9. История изменений и решения

Новые записи добавляются сверху.

## Разрешение дисплея 2K / 4K

- У каждого дисплея появилась настройка `resolution`: `1920` (2K, по длинной стороне, значение
  по умолчанию) или `3840` (4K, по длинной стороне). Для вертикального экрана физический холст
  составляет 1080×1920 или 2160×3840, для горизонтального — 1920×1080 или 3840×2160;
  элементы и раскладки масштабируются пропорционально.
- Админка показывает разрешение в карточке дисплея и в выборе предпросмотра. Старые дисплеи без
  поля автоматически нормализуются как `1920`; в `content/data.json` добавлен явный основной дисплей
  с программой всех слайдов и разрешением `1920`.
- API нормализует значение разрешения одинаково для MySQL и файлового хранилища.

## Обновление контента на сервере

- **`api/update.php`** (POST, вход + CSRF): записывает `content/data.json` на сервере в хранилище
  через `save_data` — та же нормализация и белые списки, что и обычная публикация. Данные в БД
  заменяются целиком версией из репозитория.
- **Админка → «Данные»**: кнопка «Обновить контент из репозитория» (в серверном режиме) — обновляет
  сервер сразу, минуя черновик. «Импорт data.json» по-прежнему заполняет только черновик.
- **CI (`deploy-ftp.yml`)**: после выгрузки кода делает `install.php` (если ещё не установлено)
  и `POST api/update.php` — так каждый деплой обновляет контент из репозитория, не требуя ручного
  импорта, и не падает, если БД уже есть.
- `content/data.json` обновлён из актуальной выгрузки админки (63 блюда, 27 слайдов, один основной дисплей
  с разрешением `1920`).

## Дисплеи и ориентация

- **Несколько дисплеев на одном контенте.** Новый корневой раздел `data.displays`: у каждого
  дисплея имя, ориентация и своя программа — упорядоченный список id слайдов. Плеер берёт id
  из `?display=` в адресе и крутит только эти слайды; без параметра работает как раньше
  (все слайды, вертикально). Блюда, мероприятия, слайды и настройки остаются общими.
- **Ориентация дисплея:** вертикальный (холст 1080×1920) или горизонтальный (1920×1080).
  Плеер ставит класс `landscape` на холсте и пересчитывает масштаб; горизонтальная раскладка
  переопределяет только пропорции в CSS — DOM и анимация общие.
- **Админка:** новая вкладка «Дисплеи» (список, программа, адрес экрана для копирования);
  в предпросмотре можно выбрать дисплей и увидеть горизонтальный рендер и его программу.
- **Хранилище:** в БД — новая колонка `site.displays` (JSON), добавляется миграцией
  `ensure_db_schema`; в файлах — поле в `data/site.json`. Оба режима и переключение переносят
  `displays`; `api/install.php` читает их из `content/data.json`.

## PR #6

- Автоперезагрузка экрана через X минут (Оформление → «Работа экрана»): стандартный тег
  `<meta http-equiv="refresh">` в `<head>`, чтобы экран сам восстанавливался после сбоя. Настройка
  `settings.autoRefreshMinutes` (по умолчанию 30, 0 — выключено).
- **Оптимизация анимации экрана:** невидимые слайды не рисуются и не пересчитываются, GPU-слои только
  у активного слайда, тень фото больше не пересчитывается каждый кадр, «свечение» цены анимирует прозрачность,
  фото следующего слайда декодируются заранее. На замедленном CPU «Затухание» — 20 → 55 кадров/с,
  «Куб» и «Переворот» — 1,6 → 33–39, «Колода карт» — 2 → 20. Внешний вид слайдов не изменился
  (попиксельное сравнение всех 36 слайдов).

## Принятые решения

- **Библиотеки лежат в репозитории**, CDN не используется: экран в кафе должен работать без интернета.
- **CSS Swiper переписан без nesting** (`vendor/swiper/swiper-flat.css`): встроенные браузеры ТВ
  не понимают `&`.
- **Calibri не распространяется** (лицензия Microsoft): используется системный, иначе Carlito.
- **Одна модель на всех** (`shared/model.js`): экран, админка и сборка не расходятся.
- **Публикация целиком** (полная замена данных в транзакции): проще и надёжнее построчных правок
  для объёмов кафе.
- **Анимация — на каждый показ слайда** (`gsap.context` + `revert`), чтобы ТВ-браузер не копил память
  за дни работы. Фоновые эффекты работают только у активного слайда.
